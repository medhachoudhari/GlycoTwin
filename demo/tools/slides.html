GlycoTwin

Personalized Post-Meal Glucose Digital Twin

Digital Twin Challenge 2026 · Happiest Health Summit 2026

The same meal can produce very different glucose responses. A forecast that treats everyone as average, and forgets each result, cannot adapt. GlycoTwin keeps a personal, versioned state.

The forecast → observe → update loop

STEP 1

FORECAST

Probability and 90% interval for the highest glucose in the 2 hours after a meal.

→
STEP 2

OBSERVE

The maximum glucose actually seen, recorded after the 120-minute window has closed.

→
STEP 3

UPDATE

If eligible: a new, versioned twin state. Nothing is overwritten.

Technical contribution

1 · PERSISTENT, VERSIONED TWIN

Forecast → observe → update, each eligible outcome a new version.

2 · UNCERTAINTY-AWARE

Distribution of the 2-hour maximum: 90% interval and P(max ≥ 180 mg/dL).

3 · BAYESIAN PERSONALIZATION

Closed-form sequential update of personal carbohydrate sensitivity (Model B).

4 · EXPLAIN + COMPARE

Term-by-term explanations; Models B and C compared with pre-declared rules; leakage-safe evaluation on CGMacros.

Investigational research prototype. Not a medical device. No advice on diet, medication or insulin.

The techniques are known; the contribution is their integration in one working, testable system.

Meal-event definition (decision D9)

baseline: latest valid reading ≥ 1 sensor interval before t0
t0 = logged Meal Type row
outcome window (t0, t0 + 120 min]
t0 + 120 min

Label = 1 if the maximum available glucose in the window is ≥ 180 mg/dL. The application forecasts this same target.

The release has no meal-end field: results are stated "after the logged meal-row time", never "after the end of the meal".

Source: docs/data_validity_rules.md (D1, D3, D9, section B)

Eligibility and data preparation

  • Baseline: past-only, lag-guarded so interpolated values cannot leak the future
  • Missing glucose never imputed: the peak is a lower bound
  • Meal excluded (reason logged) unless: ≥ 2 valid readings, no gap over 15 min, last reading within 5 min of the window end
  • Isolated meals only in the primary set (no other meal within 120 min)
  • Pre-meal activity: mean METs over the 4 hours strictly before the meal, ≥ 50% coverage
  • Counts always reconcile: meal rows = kept + excluded
Source: docs/data_validity_rules.md (D2, D4, D5, D6, D10)

Leakage controls

FEATURES

Only information from before the meal. Activity strictly before t0.

FOLDS

Participant-level, stratified by A1c group. No participant in both training and test.

EVALUATION

Sequential: forecast first; update only after the window has closed.

Researcher's leakage check: passed for 45 of 45 participants, on both sensors. An automated mutation test fails if a future value is introduced.

Model B: Bayesian personalization

Model B: rise = β · carbs + noise (no intercept)

Prior β ~ Normal(m₀, τ₀²) from training participants only. After each eligible meal (carbs c, observed rise r):

1/τ² ← 1/τ² + c² / σ²
m ← τ² · ( m/τ² + c·r/σ² ) (σ² = known noise variance)

Model C adds an activity term: rise = (β + γ · activity) · carbs + noise

Forecast from the current posterior (baseline b):

rise ~ Normal( m·c , σ² + c²·τ² )
P(peak ≥ 180) = Φ( (b + m·c − 180) / √(σ² + c²·τ²) )

Eligible only: window (t0, t0+120 min] closed · unusable windows excluded · back-dated forecasts refused.
A parameter update, not retraining a model.

Source: docs/model_b.md, docs/model_c.md

Three different things

RESEARCH ON CGMACROS

Retrospective, leakage-safe evaluation. Result: inconclusive for Model C; personalization not established.

APPLICATION DEMONSTRATION

The machinery working end to end on values entered by hand. Not research evidence.

CLINICAL VALIDATION

Not done. No clinical claim is made.

Limitations, safety, next steps

Investigational research prototype. Not a diagnostic tool. Not a validated medical device. Not for insulin dosing or treatment decisions. The evaluation does not establish clinical effectiveness.

  • 34 participants; the label is a lower bound (maximum available glucose)
  • Self-reported macronutrients · wrist-device activity
  • Meal-row timestamp = logging time of unknown exact meaning
  • One fold assignment · no multiplicity adjustment
  • Leakage safeguards reduce risk; independent validation still needed
NEXT RESEARCH STEPS

1. Run the prespecified key experiment on the real dataset with shuffled-history and baseline controls.
2. Test whether an activity effect exists but differs by activity level. (Neither is a result yet.)
